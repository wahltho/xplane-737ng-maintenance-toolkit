# X-Plane 737NG Maintenance Toolkit 0.18.0

Extends safe schema-3 directory migrations to support verified runtime
replacement at the same path.

- A path may be declared in both `retiredFiles` and `files`. The existing file
  is replaced only when its SHA-256 is authorized by the manifest or the
  Toolkit state proves that the same package owns its exact path and bytes.
- Unknown or locally modified legacy files continue to block the transaction.
- Same-path replacements must match the new file size and SHA-256 after
  staging. Retired paths without a replacement must be absent.
- The complete previous directory remains backed up and can be restored
  byte-for-byte. Transaction failures after backup, staging or activation roll
  back to the previous directory and Toolkit state.
- Protected aircraft content such as XLua `scripts/**` remains unchanged.
- Migration confirmations and logs distinguish same-path replacements from
  obsolete files that are removed.
- Existing schema-1 packages and schema-3 migrations that only remove renamed
  files retain their previous behavior.

This release prepares the Toolkit for a future Optimized XLua package that
keeps `plugins/xlua`, replaces XLua 1 with XLua 2 under the existing
`*/xlua.xpl` names, and removes the temporary opt2/opt3 `*/xlua2.xpl` files.
The content catalog is unchanged until that package is published separately.

Validation: all 502 automated tests pass without warnings. Focused migration
tests cover fresh installation, managed and hash-known unmanaged XLua 1,
managed and hash-known unmanaged opt3 layouts, same-path updates, repair,
modified-file blocking, exact protected-script preservation, complete restore
and injected failures after backup, staging and activation. `git diff --check`
passes.
