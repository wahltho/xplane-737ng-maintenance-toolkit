# X-Plane 737NG Maintenance Toolkit 0.23.0

You can now move or rename an aircraft directly from **Start → Move or rename aircraft**. Close X-Plane, choose an existing destination parent folder and enter an unused folder name. The Toolkit copies the complete aircraft, verifies every file, and updates its recorded installation paths and restore history before removing the old copy. Scripts, liveries, preferences and empty folders stay with the aircraft. Backups stored outside the aircraft folder remain in their existing location.

The operation needs enough space for a second complete copy, including when renaming on the same disk. It can be canceled before completion. Interrupted moves are recovered on the next launch; **Retry move recovery** and **Export move support log** are available if recovery needs attention. Do not manually delete the recovery journal or temporary move folders.

Moving does not install or repair patches. Existing destinations, nested folders, symbolic links, junctions and case-only renames are rejected. Dependencies that cannot move with the aircraft block a move to another X-Plane installation. Third-party configuration files and external updater settings are not rewritten. Windows access rules and Unix permission bits are preserved; Unix extended ACLs and extended attributes are not copied.

Validation: independent code review and the complete automated test suite passed on Windows, macOS and Linux. The Windows tests verify protected and inherited access rules and read-only files. Nine additional macOS tests passed across two actual APFS volumes, including move-back, rollback and patch, configuration and XLua restore after a move.

Installers and portable packages are provided for Windows x64, macOS Apple Silicon, macOS Intel and Linux x64. Windows packages are unsigned; macOS packages are unsigned and not notarized.
