# X-Plane 737NG Maintenance Toolkit 0.17.0

Adds safe, transactional migration support for directory-based aircraft
components whose managed runtime files change names between releases.

- Tool-package manifest schema 3 introduces declarative `retiredFiles`. A
  legacy file is removed only when its SHA-256 is explicitly allowed by the
  manifest or the existing Toolkit state proves that the same package owns its
  exact path, size and hash.
- Unknown or locally modified retired files block installation and repair. An
  optional missing legacy platform binary does not block migration.
- New package files and retired-file absence are verified in staging before an
  atomic directory swap. The complete previous directory is backed up and any
  failure restores it.
- Current-state detection and repair recognize reappeared retired files.
  Restore verifies the current generation and restores the previous runtime,
  protected paths, dependencies and retired-file contract together.
- Stable and beta channels for one package ID can require different manifest
  schemas. Existing catalog entries and schema-1 directory packages remain
  compatible.
- Migration confirmations and operation logs list retired files, replacement
  files and protected aircraft paths. X-Plane must remain closed and be
  restarted after the operation.
- Aircraft-component restore now validates the selected aircraft installation
  root correctly instead of requiring an X-Plane installation root.

This release prepares the Toolkit for a future Optimized XLua 1 to XLua 2
migration under the existing `wahltho.optimized-xlua` package ID. It does not
change the current catalog entry or publish an XLua 2 package. Stable continues
to resolve XLua 1.3.7r5 until a separately validated schema-3 XLua 2 release is
available for the beta channel.

Validation: all 489 automated tests pass without warnings. The migration suite
covers managed and hash-known unmanaged XLua 1 installations, optional missing
platform binaries, modified-file blocking, exact protected-script preservation,
file-mode preservation, repair, complete restore and injected failures after
backup, staging and target activation. `git diff --check` passes.
